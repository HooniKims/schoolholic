# 알림장 AI 다듬기 전환 및 일반 텍스트 출력 설계

## 목표

- 알림장 AI를 "새 문서 생성" 방식에서 "사용자 작성문 다듬기" 방식으로 전환한다.
- 모델 목록을 현재 운영 기준에 맞게 정리하고 기본 모델을 `gemma4:E4B`로 변경한다.
- 앞으로 생성되거나 수정되는 알림장 결과는 마크다운이 아닌 일반 텍스트로 입력하고 표시한다.
- 모바일에서 입력창을 위아래로 스와이프할 때 페이지 전체가 같이 움직이는 문제를 입력창 내부 스크롤로 한정해 해결한다.

## 범위

- 포함
- 교사 알림장 작성 페이지의 AI 모델 선택 UI
- `lib/notice-ai.ts` 기반 AI 호출 및 출력 후처리
- 교사/학부모 알림장 결과 표시 방식
- 모바일 `textarea` 터치 스크롤 처리

- 제외
- 기존에 저장된 마크다운형 알림장의 데이터 마이그레이션
- 과거 알림장 표시 포맷 일괄 변환
- 알림장 외 다른 폼 입력 UX 변경

## 사용자 결정 사항

- 기존 데이터는 유지한다.
- 일반 텍스트 포맷 전환은 앞으로 생성되거나 수정되는 내용에만 적용한다.
- AI는 문장 교정, 문체 통일, 플랫 이모지 보강 정도만 수행한다.

## 접근안 비교

### 접근안 A, 최소 변경 패치

- 모델 목록과 기본 모델을 교체한다.
- AI 프롬프트를 전면 교체해 "재작성"이 아니라 "다듬기"만 수행하게 한다.
- 마크다운 렌더링을 제거하고 일반 텍스트 표시 컴포넌트로 전환한다.
- 모바일 스크롤 문제는 `TouchScrollableTextarea` 내부에서 직접 제어한다.

장점
- 데이터 마이그레이션이 없다.
- 현재 요청 범위와 정확히 맞는다.
- 영향 범위가 알림장 기능으로 좁다.

단점
- 과거 마크다운 알림장은 그대로 남는다.

### 접근안 B, 새 포맷/구 포맷 혼합 표시

- 기존 데이터는 마크다운처럼 보여주고, 새 데이터만 일반 텍스트로 표시한다.

장점
- 표시 일관성이 더 부드럽다.

단점
- 분기 로직이 늘고 유지보수가 복잡해진다.
- 사용자가 요청한 "앞으로의 내용만"보다 범위가 크다.

### 접근안 C, 저장 포맷 버전 관리 도입

- 저장 시 format/version 메타데이터를 추가해 표시 방식을 명시한다.

장점
- 장기 유지보수에 유리하다.

단점
- 현재 요구사항에 비해 구현 범위가 과하다.

## 선택안

- 접근안 A를 적용한다.

선정 이유
- 사용자 요청을 가장 직접적으로 만족한다.
- 기존 데이터는 건드리지 않으면서 신규 작성 흐름만 안전하게 바꿀 수 있다.
- 로직과 UI 변경을 현재 코드 구조 안에서 끝낼 수 있다.

## 상세 설계

### 1. 모델 목록 재구성

대상 파일
- `lib/notice-ai.ts`

변경 내용
- 제거
- `llama3.1:8b`
- `gemma3:12b-it-q4_K_M`

- 추가
- `gemma4:E2B`
- `gemma4:E4B`

- 유지
- 삭제 대상으로 지정되지 않은 기존 모델은 그대로 유지한다.

- 기본 모델
- `DEFAULT_MODEL = "gemma4:E4B"`

- 설명 규칙
- 초보자도 바로 비교할 수 있게 각 모델 설명은 `gemma4:E4B`를 기준으로 "응답속도"와 "품질"만 짧게 표기한다.
- 예를 들면 `기본보다 빠름`, `기본과 비슷함`, `기본보다 품질 낮음`처럼 기본 모델 대비 상대 비교가 한눈에 보이게 한다.
- 모델 목록의 표시 순서는 지나치게 고성능 설명부터 시작하지 않고, 초보자가 보기 쉬운 순서로 배치한다.
- 예시 형식
- `응답속도: 기본보다 빠름 · 품질: 기본보다 낮음`
- `응답속도: 기본과 비슷함 · 품질: 기본과 비슷함`

### 2. AI 생성 로직 전면 교체

대상 파일
- `lib/notice-ai.ts`

현재 문제
- 현재 로직은 카테고리 분류, 헤더 생성, 마크다운 섹션 구성, 후처리 재정규화까지 수행한다.
- 이 구조는 "교사가 적은 메모를 조금 다듬는다"는 새 요구와 맞지 않는다.

새 동작
- 입력 텍스트의 정보량과 순서를 유지한다.
- 허용된 수정은 아래로 제한한다.
- 어색한 문장 수정
- 문체 통일
- 각 문단 또는 항목 첫머리에 과하지 않은 플랫 이모지 추가

- 금지 동작
- 내용 추가
- 임의 요약
- 카테고리 분류
- 마크다운 제목/리스트 생성 강제
- 새 일정, 금액, 제출물 등 사실 생성

출력 규칙
- 일반 텍스트만 반환한다.
- 줄바꿈과 들여쓰기를 유지한다.
- 사용자가 이미 항목형으로 적은 경우 그 구조를 최대한 유지한다.
- 사용자가 문단형으로 적은 경우 문단형을 유지한다.
- 플랫 이모지는 문단 또는 줄 첫머리에 최소한으로만 사용한다.

후처리
- 기존 `cleanMetaInfo`, 카테고리 파싱/재분류, 마크다운 정규화 계층은 제거하거나 우회한다.
- 새 후처리는 아래 정도만 유지한다.
- 빈 응답 방지
- 메타 응답 제거
- 불완전 응답 재시도

### 3. 교사 페이지 UI 전환

대상 파일
- `app/notice/teacher/page.tsx`
- `lib/i18n.ts`

변경 내용
- 버튼 문구를 "AI로 정리하기" 계열에서 "AI로 다듬기" 계열로 변경한다.
- 결과 영역도 "AI 정리 결과"가 아니라 "AI 다듬기 결과"에 맞는 문구로 바꾼다.
- 미리보기 전용 마크다운 렌더링 대신 일반 텍스트 표시 블록을 사용한다.
- 직접 수정 모드의 `textarea`는 유지한다.

표시 규칙
- 결과 표시 블록은 `white-space: pre-wrap` 기준으로 일반 줄바꿈과 들여쓰기를 살린다.
- 링크 자동 변환, 마크다운 헤더, 리스트 스타일링은 신규 결과에 적용하지 않는다.

### 4. 학부모 페이지 표시 전환

대상 파일
- `app/notice/parents/page.tsx`

변경 내용
- 학부모 페이지도 동일한 일반 텍스트 표시 블록을 사용한다.
- 신규 저장분은 줄바꿈과 들여쓰기가 그대로 보이게 한다.

호환성
- 기존 마크다운형 데이터는 이번 작업에서 변환하지 않는다.
- 다만 신규 흐름 기준 렌더러는 일반 텍스트를 우선으로 본다.

### 5. 모바일 입력창 스크롤 수정

대상 파일
- `components/TouchScrollableTextarea.tsx`
- 필요 시 `app/globals.css`

현재 문제 가설
- 전역 `overscroll-behavior: contain`과 기존 터치 이동 핸들러만으로는, 입력창이 스크롤 경계에 있을 때 페이지 스크롤 전파를 완전히 막지 못한다.
- 특히 모바일 브라우저에서는 상하 경계에서 바운스/체인 스크롤이 발생할 수 있다.

수정 방향
- `touchstart`에서 시작 위치와 스크롤 위치를 저장한다.
- `touchmove`에서 현재 방향과 경계 상태를 계산한다.
- 텍스트 영역이 실제로 스크롤 가능한 경우에는 내부 스크롤만 갱신한다.
- 맨 위에서 아래로 끌거나 맨 아래에서 위로 끄는 경계 상황에서도 기본 스크롤 체인이 페이지로 넘어가지 않도록 `preventDefault`를 유지한다.
- 필요 시 `touch-action`과 `overscrollBehaviorY`를 보강하되, 다른 입력 컴포넌트에 부작용이 없도록 범위를 `TouchScrollableTextarea` 내부로 제한한다.

성공 기준
- 모바일에서 긴 텍스트를 수정할 때 입력창 안에서만 상하 이동한다.
- 같은 제스처가 페이지 전체 스크롤로 새지 않는다.

## 데이터 흐름

1. 교사가 날짜와 원문 메모를 입력한다.
2. 선택한 모델로 `summarizeNote`를 호출한다.
3. AI는 원문을 유지한 채 최소 보정된 일반 텍스트를 반환한다.
4. 교사는 결과를 직접 수정할 수 있다.
5. 저장 시 기존 구조대로 `originalContent`와 `summary`를 Firestore에 저장한다.
6. 학부모 페이지는 저장된 `summary`를 일반 텍스트로 표시한다.

## 오류 처리

- AI 응답이 비어 있거나 메타 설명만 반환되면 재시도 후 실패 메시지를 표시한다.
- API 키 누락, 네트워크 실패, 서버 오류는 기존 사용자 메시지 흐름을 유지한다.
- 모바일 스크롤 수정은 실패해도 텍스트 입력 자체가 막히면 안 된다.

## 테스트 계획

정적 검증
- `npm run lint`

수동 검증
- 교사 페이지에서 모델 목록이 요청한 구성으로 보이는지 확인
- 기본 선택 모델이 `gemma4:E4B`인지 확인
- AI 결과가 마크다운 제목/섹션 없이 일반 텍스트로 나오는지 확인
- AI가 새 내용을 덧붙이지 않고 입력문을 다듬는 수준인지 확인
- 줄바꿈과 들여쓰기가 교사/학부모 페이지에서 그대로 보이는지 확인
- 모바일 환경에서 긴 입력 내용을 스와이프할 때 페이지 전체가 움직이지 않는지 확인

## 리스크와 대응

- 기존 마크다운 렌더러 제거로 예전 데이터 표현력이 떨어질 수 있다.
- 대응: 이번 작업 범위는 앞으로의 내용만으로 제한하고, 과거 데이터 변환은 하지 않는다.

- 새 프롬프트가 지나치게 보수적으로 동작하면 변화가 작아 보일 수 있다.
- 대응: 문장 교정과 문체 통일, 플랫 이모지 추가를 명시하되 내용 확장은 금지한다.

- 모바일 브라우저별 터치 이벤트 차이가 있을 수 있다.
- 대응: 경계 스크롤 전파 차단을 컴포넌트 내부 로직으로 처리하고, 전역 CSS 의존도를 낮춘다.
